Wisp: a neutrino event display in one HTML file

Devin Gaughan · November 24, 2026 · 6 minute read

Neutrinos pass through nearly everything without leaving a mark. When one finally does interact inside a detector, what it leaves behind is a thin trail of charge. Wisp is my tool for looking at those trails in a browser.

The project used to be called NuView. I renamed it this week after the will-o'-the-wisp, the faint light that drifts through the dark and cannot be caught, which seemed right for a particle with the same habits.

The problem

The MicroBooNE experiment at Fermilab has published open data samples from its liquid argon time projection chamber, or LArTPC. The standard tools for viewing that kind of data are desktop applications tied to the ROOT and LArSoft software stack. They are powerful, and they take real effort to install if you are not already inside a physics collaboration.

I wanted the opposite: something a curious person could open in five minutes. Wisp is a single HTML file with no dependencies and no build step, fed by one short Python script.

What the detector records

A LArTPC is a large tank of liquid argon with an electric field across it. A charged particle crossing the tank knocks electrons loose, and the field drifts those electrons sideways onto three planes of wires. Each hit therefore carries two numbers: which wire collected it, and when. Plot wire number against drift time and you get a picture of the track, seen from three angles at once.

That is the main view in Wisp: three canvases, one per wire plane, with hits colored by how much charge they deposited.

Getting the data into a browser

The open samples are HDF5 files, a format browsers cannot read directly. The extraction script pulls one event out and writes it as JSON with three parts: metadata about the neutrino, the hits on each plane, and the list of true particles from the simulation.

The interesting step is matching hits to particles. A single hit can contain energy from several particles, so the script assigns each hit to whichever one deposited the most. It does that with a sort:

order = np.argsort(ed_en)   # ascending energy
hit2g4 = {}
for j in order:
    hit2g4[int(ed_hit[j])] = int(ed_g4[j])   # later writes win

Writing the deposits in ascending order means the largest one for each hit is written last and overwrites the others. Hits with no match are cosmic-ray background, and Wisp draws them dimmed.

Drawing without a library

Everything is drawn on plain 2D canvases. Two details mattered more than I expected.

Clipping the color scale. A few hits in every event are far brighter than the rest. Scaling colors to the maximum makes everything else look black, so Wisp sets the top of the scale at the 97th percentile:

const sorted = [...d.charge].sort((a, b) => a - b);
const qhi = sorted[Math.floor(sorted.length * 0.97)] || 1;

Writing the 3D view by hand. The 3D view shows straight segments for the true particle paths inside an outline of the detector. That is a small enough job that a rotation and an orthographic projection cover it, with no WebGL:

const proj = v => {
  const x = v[0] - ctr[0], y = v[1] - ctr[1], z = v[2] - ctr[2];
  const x1 = x * cy + z * sy, z1 = -x * sy + z * cy;   // rotate about y
  const y1 = y * cx - z1 * sx;                         // tilt about x
  return [cv.width / 2 + x1 * S + panX, cv.height / 2 - y1 * S + panY];
};

Try it

  1. Download the repository from github.com/devin-gaughan/wisp.
  2. Open index.html in a browser.
  3. Drop one of the included event_*.json files onto the page, then switch between Charge and Truth, and between 2D Planes and 3D.

Next on the list is a reconstruction mode, which colors hits by what the experiment's pattern-recognition software decided, so you can compare it against the truth.
